# 员工智能助理 A 阶段部署与验收

接口路径、请求字段和响应结构见 [A 阶段接口文档](CHUANGJIE-ASSISTANT-STAGE-A-API.md)。

## 已实现

- 独立 `chuangjie-module-assistant`；不依赖旧 AI、PMS 知识库或未启用的 HRM/WMS 模块。
- 租户独立总开关、内网模型地址与名称、保存期限、请求上限。
- 租户管理员查看总览、配置、员工开通和无正文的基础审计。
- 已开通员工的全局悬浮窗、通用问答、本人历史会话。
- 每次请求重新校验租户、账号状态、开通状态；模型地址只接受内网 HTTP，禁止重定向与代理。

## 部署顺序

1. 备份目标 MySQL 数据库。
2. 执行 `sql/mysql/assistant-stage-a-20260926.sql`。此迁移只建助理表并添加当前管理菜单，不修改系统用户表或旧 AI 表。
3. 核对 `system_menu` 新菜单及本租户 `tenant_admin` / `super_admin` 的 `system_role_menu` 关联，重新登录或刷新菜单缓存。
4. **新租户**：在该租户使用的 `system_tenant_package.menu_ids` 中纳入助理管理菜单，否则新建租户的管理员不会看到菜单。按套餐的业务政策决定是否纳入，不应无条件给所有套餐开放。
5. 部署后端与前端。租户管理员进入「智能助理管理 → 全局配置」，填写本租户内网模型服务地址（OpenAI 兼容 `/v1/chat/completions`）及模型标识，先保存并测试，再打开总开关。
6. 在「使用人员」开通测试账号，刷新员工页面，验证右下角悬浮窗。未开通账号及禁用账号均不应获得入口；直接请求 `/assistant/chat/ask` 也应失败。

迁移和真实模型连接**尚未在此开发环境执行**。如果服务使用非 MySQL 数据库，需要按相同表结构另做迁移；当前 SQL 与仓库本地配置中的 MySQL 示例一致。

## 本阶段验收

| 场景 | 预期 |
| --- | --- |
| 租户 A 与 B 配不同模型地址 | 各租户只读取自己的配置；会话和审计不串租户 |
| 总开关关闭或员工未开通 | 悬浮窗隐藏，直接调用问答接口被拒绝 |
| 员工开通后停用 | 后端新请求立即拒绝，悬浮窗在下一次状态刷新时消失 |
| 模型地址为公网或 HTTPS | 保存失败；不会回退到云模型 |
| 已开通员工提通用问题 | 本地模型返回答案并保存本人会话 |
| 员工访问别人会话 ID | 后端拒绝，不返回正文 |
| 管理员查看审计 | 只见元数据，无员工问题和答案正文 |
| 保存期限到期 | 每日清理过期消息、会话与审计 |

## 验证情况与限制

- Maven 主服务编译通过；助理模块针对性测试通过。
- 前端 Vite 打包通过。全仓 Vue 类型检查仍被其他页面原有的 7 处错误阻断；新增助理文件未出现在错误列表。
- A 阶段的对话是**通用试运行**，尚未接入公司业务数据或独立知识库。模型回答不能作为营业额、入库、面试等项目数据来源。
- 目前模型接口未提供凭据配置；推理服务应在内网限制访问。多租户若共享同一推理服务，仍需在服务端隔离日志与缓存。
- 租户管理员更换套餐时，现有租户逻辑会按套餐重算菜单权限；应把助理管理菜单加入目标套餐后再更换。
