# 创界员工智能助理功能设计（待评审）

**版本**：v0.1  
**日期**：2026-09-26  
**状态**：功能设计；A 阶段已验收，B 阶段代码已实现但尚未执行迁移或连接真实内网向量模型  
**适用项目**：`chuangjie-backend`、`chuangjie-frontend`

## 1. 目标与边界

系统管理员在管理后台统一配置全公司的内网智能助理。已开通的员工在业务页面使用悬浮窗，用自然语言查询自己有权查看的实时业务数据、检索助理自己的公司知识库，并获得带来源的答复。

首期只读：不修改单据，不创建任务，不发送消息。图片找相似产品、Word 生成、长期个人记忆和执行动作列为后续阶段。助理不依赖现有 `chuangjie-module-ai`，不连接 PMS 现有知识库；它可以使用现有登录、组织和业务服务，但独立维护模型配置、知识、会话和审计数据。

“开通助理”只赋予使用入口，不增加业务数据权限。模型负责理解语义和组织回答；身份、授权、数据范围、指标口径和数据查询由后端控制。

## 2. 项目现状与设计依据

| 已核实事实 | 对设计的影响 |
| --- | --- |
| 当前主构建启用 System、Infra、BPM、OA、PMS；HRM、WMS、旧 AI 未接入主构建 | 首期功能不得依赖 HRM、WMS 或旧 AI 才能启动；对应指标标记为“待接入” |
| 系统用户 `system_users` 负责登录，含部门与岗位信息 | 助理使用登录用户 ID 作为首期身份锚点 |
| HRM 员工档案有可为空的 `userId`，可以关联系统用户 | HR 档案不是每个登录用户必有的资料；未来接入时作为补充信息 |
| 系统角色已有部门范围等规则 | 这些规则不自动覆盖店铺、仓库、项目及外部数据，需要逐数据域适配 |

以上是基于仓库代码的事实，不代表生产环境的数据、模型服务或外部营业额接口已经可用。

## 3. 用户与权限

| 角色 | 可操作内容 |
| --- | --- |
| 租户内系统管理员 | 统一配置本租户的模型、使用人员、数据能力、助理知识库和审计策略；不得管理其他租户 |
| 平台超级管理员 | 管理平台级安全底线和租户管理权限；进入具体租户的配置或数据时仍需显式授权与留痕 |
| 已开通员工 | 使用悬浮窗，查看本人会话和有权访问的业务数据、知识 |
| 未开通员工 | 不显示悬浮入口；直接请求助理接口也被拒绝 |

多租户为确定需求：每个租户可以分别配置模型服务、总开关、员工开通范围、数据能力、知识库和会话保存期限。所有配置、知识、会话与审计按租户隔离；不同租户可以选不同内网模型或模型地址。即使多个租户共享同一推理服务，也不得共享请求缓存、知识索引、日志访问权限或会话数据。“全公司统一配置”指公司所在租户内统一管理。管理员管理功能开关和授权规则，不默认获得员工对话正文或超出原有业务权限的数据。

图片检索、Word 模板、个人记忆策略和执行动作审批属于后期扩展。首期不显示尚不可用的空菜单；菜单结构预留扩展位置。

### 4.1 总览

展示全局启停状态、内网模型连接状态、已开通员工数、近 7 日提问量、成功/拒绝/失败数量、知识库索引状态及待处理反馈。可以跳转到对应配置页；总览不承载具体配置表单。

### 4.2 全局配置／基础设置

每个租户独立设置：助理总开关、单人每分钟请求上限、单次问题长度上限、单次查询时间上限、历史会话保存期限、超时提示文案。A 阶段默认总开关关闭、保存 30 天、每人每分钟最多 10 次；管理员可将保存期限设为 1～365 天。系统按期限自动清理。关闭时本租户员工助理接口停止提供问答，已有记录按保留策略处理。

### 4.3 全局配置／模型配置

租户内系统管理员统一配置本租户模型，不为每个员工部署模型。不同租户允许使用不同配置。字段：用途（语义规划、答案生成、文本向量化；后期增加图片向量化）、内网服务地址、服务端模型标识、超时时间、并发上限、启用状态、最近测试结果。Qwen3-32B 可以作为语义规划和答案生成的候选模型，实际模型标识以本地推理服务暴露的名称为准。

操作：新增或编辑配置、使用合成测试问题测试连接、启停配置、查看故障。地址必须符合内网访问策略，禁止配置公网模型，禁止自动回退到云模型。密钥等敏感配置只在服务端保管，页面不回显。连接测试不得发送真实业务数据。

模型连接成功只证明服务可访问，不等于指标查询准确；准确度需用项目问题集单独验收。

### 4.4 全局配置／安全设置

配置允许的模型网络范围、敏感字段输出规则、会话和审计保留期限、管理员查看审计内容的权限。保留配置变更记录，记录操作者、时间、变更前后值（密钥除外）。首期不提供“关闭权限校验”的选项。

### 4.5 使用人员／员工开通

数据来源是已有登录账号，可按姓名、账号、部门、岗位、账号状态、助理状态筛选。操作为单人开通、单人停用、按当前筛选结果批量开通或停用。默认所有现有及新增账号均关闭。批量操作写入明确的账号清单，不自动给未来加入部门的员工开通；这样人员调岗和新建账号不会意外扩大可用范围。

账号禁用、删除或助理总开关关闭时立即失去使用权。开通记录需保留操作人、时间与原因。无需修改系统用户的基础资料才能开通助理。

### 4.6 使用人员／使用范围

展示员工当前可使用的助理能力、各数据域是否已接入、知识可见范围摘要和不可用原因。这里显示的是**有效权限预览**，不能在该页面直接绕过业务模块权限给员工授权。部门和岗位用于筛选与展示，不是敏感数据访问的唯一依据。

### 4.7 数据能力／数据源

登记内部业务模块或外部系统的数据连接，显示负责人、连接方式、同步/实时模式、最近更新、健康状态。外部店铺营业额属于外部数据源，需先确定接口、字段、同步周期及失败重试。数据源连接信息仅管理员可管理；原始凭据不返回前端。

### 4.8 数据能力／指标与口径

每个指标至少登记：编码、名称、业务说明、来源、统计时间字段、时区、过滤状态、聚合规则、可用维度、口径版本、负责人、启用状态。员工问法可以变化，模型映射到已登记的指标；新增问法通常不需新增一套接口，但新增数据域或业务指标需要经过登记与验收。

首批候选指标与待确认口径：

| 指标 | 当前状态 | 必须明确的口径 |
| --- | --- | --- |
| 每店本月营业额 | 外部系统接口待接入 | 营业额含税与否、退款与取消订单、时区、店铺映射、数据延迟 |
| 今日异常入库单数 | WMS 源码存在但主构建未启用 | 异常标记字段、单据状态、按创建还是发现异常时间统计、仓库范围 |
| 今日面试数 | HRM 源码存在但主构建未启用 | 按计划面试时间还是创建时间、取消和改期是否计入、部门范围 |

指标配置状态分为“草稿、待验证、已启用、已停用”。只有数据源、权限映射和样例结果验证通过后才能启用。

### 4.9 数据能力／权限映射

每个数据域单独配置权限来源与强制范围，例如店铺权限、仓库权限、部门范围、项目成员关系及字段脱敏。模型输出的用户 ID、角色、SQL、表名或权限声明均不可信。后端从当前登录态取得用户和租户，再调用该业务域的权限服务；权限无法确定时拒绝查询。不得以“系统管理员给员工开通助理”替代业务授权。

### 4.10 数据能力／查询记录

显示请求时间、员工、数据域、指标、权限结果、耗时、结果行数、数据更新时间和失败原因。不在普通查询日志保存完整敏感结果。

### 4.11 独立知识库／知识库列表

新建公司级或部门级知识库，管理名称、用途、负责人、启停状态、文档数、索引状态。助理知识库完全独立于 PMS 和旧 AI 数据表、检索服务及配置。

### 4.12 独立知识库／文档管理

上传、更新、停用和删除文档；显示版本、解析状态、索引状态、更新时间、来源及负责人。文档内容解析、分段、向量化与检索均在内网完成。文档变更后重新索引；停用或撤销权限后不得继续出现在检索结果中。回答引用文档名称和版本。

### 4.13 独立知识库／可见范围

按员工、部门或明确授权群组设置可见范围。检索候选时和返回内容前均校验当前员工权限。知识文档只作为参考资料，文档中的指令不得改变系统规则或数据访问权限。

### 4.14 审计与反馈／对话审计

“管理员调阅”指管理员打开员工与助理的聊天正文。首期不提供管理员任意浏览或搜索员工完整会话的功能。普通审计只显示使用人、时间、意图、使用的数据域/文档、是否被拒绝、耗时与错误码；员工可查看自己的会话。员工主动提交错误反馈时，可明确选择附带该条问答片段供本租户有反馈处理权限的管理员查看；记录查看人和时间。未被员工分享的聊天正文不在反馈页展示。历史会话和反馈片段按本租户设置的期限清理。

### 4.15 审计与反馈／错误反馈

员工对答案标记“不准确、数据过期、无权限却显示、没有回答”等类型，并可补充说明、选择是否附带该条问答片段。管理员只能查看员工选择分享的片段，可分配负责人、记录处理结论，关联指标口径、知识文档或模型配置的修订版本。

### 4.16 审计与反馈／运行日志

记录本地模型故障、知识索引失败、数据源同步失败、查询超时和权限拒绝统计。日志不得输出模型密钥、原始敏感数据或完整文档内容。

## 5. 员工端悬浮窗

已开通员工登录后，在业务系统布局右下角看到入口；点击展开，关闭后仍停留在当前页面。悬浮窗支持连续提问、显示来源/统计时间、查看自己的历史会话和反馈错误。移动端应避开页面主要操作区。账号停用、助理权限被撤销或全局关闭时，入口消失，接口同步拒绝。

回答分为“已授权且有数据”“已授权但无数据”“无权限”“数据域未接入”“数据源或模型故障”五类，文案必须区分，不能把故障说成查询结果为零。缺少关键条件（例如要查哪个月）时先追问，不猜测。

## 6. 处理流程与安全边界

```text
员工提问
  → 验证登录、租户、账号状态、助理开通状态
  → 内网模型识别意图并生成受限查询计划
  → 后端校验数据域/指标/字段/时间范围及业务权限
  → 调用只读业务适配器或带 ACL 的知识检索
  → 校验结果字段和可见范围，形成带来源的答案
  → 写入必要审计，返回悬浮窗
```

查询计划只允许从已登记的域、指标、维度、过滤项中选择；禁止模型直连数据库或执行其生成的任意 SQL。单次查询有行数、时间范围、耗时与结果大小上限。知识库内容和用户问题都不能作为提升权限的指令。内网推理服务不应把敏感请求写入可被普通人员读取的日志。

## 7. 分阶段交付与验收

| 阶段 | 交付内容 | 最低验收 |
| --- | --- | --- |
| A：管理与入口 | 独立模块、全局开关、内网模型配置、员工开通、悬浮窗、审计基础 | 未开通员工无入口且接口拒绝；停用立即生效；模型只访问内网 |
| B：独立知识库 | 上传、解析、索引、ACL 检索、来源引用 | 不同权限员工对同一问题只能获得可见文档；撤权后失效 |
| C：业务数据 | 语义查询计划、指标口径、权限适配、首批已验证指标 | 同一问题不同身份只返回各自范围；口径与业务系统对账 |
| D：扩展 | 个人记忆、图片找相似商品、Word 生成 | 分别设计隐私、商品图片授权与模板验收；不混入前三阶段的承诺 |

阶段 A 的模型连接与悬浮窗只是基础设施；不能以此宣称已支持营业额、WMS 或 HRM 问答。阶段 C 的具体先后顺序应由真实数据源可用性决定。

## 8. 开发前需要定稿的事项

1. **已确定：多租户**。每个租户单独配置模型、能力、使用人员、知识库和会话保存期限；跨租户严格隔离。
2. **暂不确定：首批指标**。后续从已启用模块挑选可对账指标；外部营业额、WMS、HRM 等排期随后决定。
3. **暂不确定：外部营业额接口**。接口文档、店铺标识、授权映射与口径后续明确；在此之前不能启用该指标。
4. **已确定：会话保存期限可配置**。A 阶段实现默认 30 天、可选 1～365 天；管理员普通审计只看元数据。员工主动附带单条问答片段的反馈流程安排在后续阶段。

以上事项未确定时，可以先开发阶段 A 的管理与入口，但不能开启对应业务数据能力。
