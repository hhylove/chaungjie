# 创界人员档案一期：账号衔接

## 现状与范围

- 当前运行的后端未启用 `chuangjie-module-hrm`，本地 MySQL 也没有 `hrm_employee` 表。该模块和前端 `hrm/employee` 页面不能当作已上线功能继续叠加。
- 已运行的 `system_wecom_user` 保存企微身份，`system_users` 保存登录账号。企微授权登录已经按企微 userid 查映射，再校验账号状态。
- 一期以原型的人事行政「人员档案」为目标，建立最小可用的人事档案；不复制旧 HRM 的合同、薪酬等全部功能。
- 建档、启用账号、授予角色是三个独立动作。建档不自动启用，企微同步也不改变账号状态或角色。

## 数据归属

| 数据 | 唯一维护入口 | 关联方式 |
| --- | --- | --- |
| 企微 userid、企微部门、最近同步 | 企业微信同步 | `system_wecom_user.system_user_id` |
| 登录名、密码、启停、角色、权限 | 系统账号 | `system_users.id` |
| 工号、入离职状态、岗位、人事资料 | 新人员档案 | 唯一的 `user_id`，允许为空 |

人员档案以 `tenant_id + user_id` 保证一个账号最多绑定一份有效档案；没有账号的待入职人员也可以建档。企微同步只更新其镜像和已定义的系统账号字段，不直接改人事档案中的人工核实资料。手机号在未核验前仅作联系信息，不用于短信登录和找回密码。

## 管理员操作流程

1. 在「人事行政 → 人员档案」新增待入职档案，工号由服务端生成，不填账号、不启用账号。
2. 可提前在「企业微信同步」拉取并核对人员；同步预建的系统账号保持禁用，不计入在职。
3. 到约定日期且本人实际到岗后，由同时拥有人事修改、系统账号查询和启停权限的管理员确认到岗，关联核实过的禁用账号并启用；角色授权仍由有独立权限的管理员办理。
4. 员工用企业微信授权登录，不依赖手机号。账号密码是备用方式，需单独设置可告知的登录名及一次性初始密码；现有随机密码只能重置，不能读取。

## 页面与接口边界

- 人员档案列表：姓名、部门、岗位、入离职状态、企微关联状态、账号启停、建档状态；未建档人员可从企微映射的系统账号发起建档。
- 人员详情：「人事资料」和「账号与企微」分区。账号启停复用系统权限校验；角色分配复用 `system:permission:assign-user-role`，不能只凭 `personnel:archive:update` 授权。
- 后端提供人员档案列表、详情、创建、更新及按账号查询未建档人员的接口。查询按租户和数据权限过滤；敏感字段不从企微镜像直接暴露给普通人事角色。
- 离职办理需单独确认账号停用结果；同步不能将离职账号重新启用。服务账号和系统管理员账号仍在「用户管理」处理，不要求有人事档案。

## 开发顺序与验收

1. 建立最小人员档案表、菜单和新增待入职档案接口；工号自动生成，新增时不接受账号绑定或在职状态。
2. 做列表与详情，显示账号状态；新增档案后仍不能登录。到岗确认接口须核对日期、禁用账号及重复绑定，并在同一事务中关联档案和启用账号。
3. 角色授权入口沿用系统权限；无权限时接口仍拒绝。完整入职事项、合同与薪酬审批仍待 BPM 接入，不将建档误标为流程完成。
4. 使用试点账号验收企微授权、启用、停用和跨租户隔离。当前用户要求先跳过这一步的实际登录验证，发布前仍应补做。
