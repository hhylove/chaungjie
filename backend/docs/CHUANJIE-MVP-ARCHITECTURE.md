# 川界第一期架构与 MVP 范围

## 1. 产品定位

川界第一期面向电商企业内部经营管理，覆盖“商品—订单—采购—库存—仓储—财务对账”的核心经营链路。MES、IoT、开放 SaaS 和对外商业化作为后续扩展能力。

## 2. 第一阶段目标

让企业能够在一个系统内完成：

1. 商品和 SKU 管理
2. 多渠道订单汇总与处理
3. 采购、入库、出库和库存盘点
4. 仓库及库位管理
5. 售后、退款和退货处理
6. 基础经营报表
7. 组织、角色、权限和操作审计

## 3. 模块边界

### 保留并改造

- system：用户、组织、角色、菜单、权限、字典、日志
- infra：文件、消息、代码生成、定时任务、数据字典
- report：基础报表能力
- pay：仅保留后续需要的支付和对账抽象

### 第一阶段新建或重构

- commerce：商品、类目、品牌、SKU、渠道
- order：订单、订单明细、发货、售后、退款
- supply：供应商、采购单、采购入库
- inventory：库存、库存流水、盘点、调拨
- warehouse：仓库、库区、库位、出入库
- finance：应收应付和渠道对账基础模型

### 暂不进入第一期核心范围

- 完整 MES
- 真实设备接入和 IoT 实时数据
- 复杂营销中心
- 完整 CRM
- 多组织跨集团结算
- SaaS 套餐计费和开放市场

## 4. 建议工程结构

```text
chuangjie/
├── chuangjie-dependencies
├── chuangjie-framework
├── chuangjie-server
├── chuangjie-module-system
├── chuangjie-module-infra
├── chuangjie-module-commerce
├── chuangjie-module-order
├── chuangjie-module-supply
├── chuangjie-module-inventory
├── chuangjie-module-warehouse
├── chuangjie-module-finance
└── chuangjie-ui-admin
```

第一阶段建议采用模块化单体，不急于拆分微服务。先保持事务一致性和交付速度，等订单、库存、采购等边界稳定后再决定是否拆分。

## 5. 多租户设计原则

第一期就预留多租户，但优先采用共享数据库、共享表、`tenant_id` 隔离的方案。

- 所有租户业务表必须包含 `tenant_id`
- 平台配置与租户业务数据分离
- 超级管理员不能默认访问全部租户业务数据
- 关键查询必须经过租户上下文校验
- 库存、订单、采购和报表禁止跨租户统计
- 后续可为大客户升级独立数据库

## 6. 核心业务主链路

```text
商品/SKU
  → 渠道订单
  → 订单审核
  → 库存锁定
  → 拣货/出库
  → 物流发货
  → 售后/退款

库存不足
  → 采购申请
  → 采购订单
  → 采购入库
  → 可用库存增加
```

## 7. 后续扩展方向

- MES：生产订单、BOM、工艺、报工、质检、追溯
- IoT：设备档案、点位、采集、告警、能耗
- 移动端：审批、库存盘点、拣货、收货、售后
- 小程序：客户查询、订单、售后、供应商协同
- SaaS 商业化：套餐、试用、订阅、计费、租户自助开通

## 8. 实施顺序

1. 工程品牌和包结构改造
2. 多租户与权限底座
3. 商品、订单、库存、仓储
4. 采购与供应商
5. 售后与财务对账
6. 移动端和小程序基础能力
7. 报表、审计和运营后台
8. MES、IoT 和 SaaS 商业化
