# 人事行政管理：原型对齐与生产落地

> 对照 `创界平台原型/hr/app.js`、`engine.js`、`operations-ui.js` 和本地原型服务。原型里的 35 人、待办、物资等均为浏览器中的演示数据，生产系统不得沿用其数字或模拟身份。

## 页面与后端对应

| 页面 | 原型交互 | 生产数据及接口 |
| --- | --- | --- |
| 人员 | 人数卡、风险卡、名册筛选、六页签员工抽屉 | `hradmin_employee`；`GET /hradmin/employee/overview/page/get`，`POST create`，`PUT update`；账号启停与角色复用 System |
| 招聘 | 用人需求、候选人阶段、录用转员工 | 后续招聘需求、候选人、跟进记录；批准后才可建待入职档案 |
| 流程 | 入转调离、任务、期限、凭证、异常升级 | 复用 BPM 流程实例与任务；审批完成后更新人事档案事实 |
| 制度与档案 | 文件版本、审批、生效、签收 | 文件主表、不可覆盖的版本、签收任务与证据，附件走文件服务 |
| 行政物资仓库 | 库存、采购入库、派发归还、销售 | 物资、采购单、库存流水、领用人；库存变动须有单据和事务 |

单侧栏入口，五个内部页签。员工抽屉的“基本信息、任职薪酬、合同社保、培训制度、资产权限、人事记录”是同一员工 ID 的跨业务视图。薪酬、证件等敏感数据必须有独立的后端权限和审计，不能因为有人事查询权限就返回。培训签收、物资状态必须来自业务记录，不能由页面写死“已完成”。

## 本批实现与开发顺序

本批先形成真实人员数据闭环：统计卡、合同与社保风险、名册、抽屉中已登记的事实、新增和编辑。只有已建档人员进入统计；企微同步账号不自动算在职。未登记合同和社保显示“未登记”。BPM 接入前“今日待办”不显示假数字。其余四个页签接入真实后端前仍不可办理；按“招聘 → 流程 → 制度与档案 → 行政物资仓库”逐个完成页面、数据表、接口、权限和验收。

已执行初始脚本的环境补运行 `sql/mysql/hradmin-employee-workbench-20260928.sql`。试用期按在职且结束日未到统计；异常按合同已过期或已登记未参保统计；未来七天按合同结束日统计。未登记不代表正常，资料完整性提醒后续单独实现。查询权限目前只应授予可看本租户全员的管理员；部门范围与字段级权限上线前，不得下放给普通主管。

## 范围与命名

新建 `chuangjie-module-hradmin`（Java 包 `com.chuangjie.module.hradmin`、接口 `/hradmin`、表 `hradmin_`）；旧 HRM 只作参考。创业者业务另设模块。一期先做人员档案与企微账号衔接，不把招聘、薪酬、合同、物资流程提前塞进档案表。侧栏只有“人事行政管理”一个入口，人员、招聘、流程、制度与档案、行政物资仓库放在页面内切换。

## 数据责任

企微同步维护成员与部门来源；System 维护账号、角色、登录权限；Hradmin 维护工号、任职日期、任职状态及人事档案。档案与系统账号按租户唯一关联，候选人与待入职人员允许无账号。部门、姓名等同步字段在人员页展示来源，不从档案反写企微镜像。

## 办理边界

一期有账号管理权限的管理员在人事页直接启停账号、分配角色；档案编辑权限本身不能获得账号权限。页面调用 System 既有受权接口，System 服务是唯一执行入口。将来增加审批时，审批通过节点仍调用同一 System 服务，不建预留空审批表。

## 一期接口与验收

- 档案分页、详情、创建、更新；支持从已关联企微的系统账号建档。
- 接口：GET `/hradmin/employee/page`、GET `/hradmin/employee/get`、POST `/hradmin/employee/create`、PUT `/hradmin/employee/update`；请求示例见 `EmployeeArchiveController.http`。
- 数据脚本：`sql/mysql/hradmin-employee-20260927.sql`。先在测试数据库执行，再启动服务；脚本建表及菜单，不自动给普通角色授权。
- 已执行旧版三级菜单脚本的环境，再运行 `sql/mysql/hradmin-menu-flat-20260928.sql` 迁移成单入口；当前未开发的页签暂不可操作。
- 多租户启用时，还需由系统管理员把新菜单加入目标租户套餐，并给该租户的人事管理员角色分配查询、新增、修改权限；若需在人员页办理账号与角色，还需分别授予 `system:user:query`、`system:user:update` 与 `system:permission:assign-user-role`。脚本不批量给全部租户开通。
- 一期仅将 `hradmin:employee:query` 授予可查看本租户全体人员的管理员；后端使用租户过滤及接口权限校验。部门级人事数据范围尚未上线，未授权角色不得获得此权限，也不能用前端隐藏代替后端授权。
- 一租户同一账号最多一份档案；无账号档案用稳定工号区分；更新不自动启用账号。
- 验收包括重复绑定、跨租户访问、禁用账号建档、账号权限分离、企微再次同步后档案不重复。
