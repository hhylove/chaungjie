# 人事行政首批实现与原型对照

对照 `创界平台原型/hr/app.js`、`hr/engine.js` 和 2026-09-27 流程规则。原型中的人员、待办和审批人是演示数据，生产端只展示真实记录。

## 已实现

| 原型节点 | 生产实现 |
| --- | --- |
| 用人申请 → 审批 → 候选人 → 面试 → 评价 → 录用审批 | 招聘需求、候选人、跟进记录和分节点权限；审批通过才可继续，名额满后禁止转档 |
| 录用转员工 | 创建待入职档案；自动生成内部编号、单独保存约定月薪、生成 18 项入职事项；不创建或启用账号 |
| 直接新增原有人员 | 记录实际已在职的人员和薪酬；不补造招聘、到岗或入职事项 |
| 入职前 → 到岗 → 入职当天 → 入职后 | 按原型节点、负责角色和阶段办理，保存办理依据；到岗后进入独立“试用期”状态 |
| 系统权限开通 | 先确认到岗，再核验禁用企微账号与档案姓名，由具备人事及系统权限者开通；系统用户页禁止直接启用企微同步账号 |
| 人员名册 | 不展示或填写工号；人员、招聘可切换；薪酬仅独立权限可读写 |

社保事项必须明确确认“已参保”并记录证明。员工本人事项由已关联的账号办理。原有在职人员可单独核验后开通账号。

## 仍与原型有差异

- 原型的转正、调岗、调薪、晋升、离职、续签等流程尚未接入。因此试用期不会因为日期到期而自动变成“在职”；需完成后续转正流程。
- 本批招聘与入职办理尚未接入公共流程的两日审批时限、撤回/终止、驳回整改及统一待办；这些规则不能视为已验收。
- 人员页“今日待办”、制度签收、培训、资产和人事记录尚无完整业务数据，页面不伪造完成情况。流程、制度与档案、行政物资仓库页签暂不可办理。
- 原型用模拟角色切换；生产端按权限点控制。直属上级权限目前尚未校验其与具体员工的管理关系，授予范围应限于可信人员，后续必须补齐数据范围。
- 薪酬档案已有独立表和读写权限；原有人员薪酬标记“已登记待核验”。调薪与正式核薪仍须后续审批流程。
- 系统用户页禁止直接启用企微账号后，已开通过的企微账号若因安全原因再次禁用，当前没有自助复启流程，需后续在人事端增加核验复启。

## 部署顺序

先执行 `sql/mysql/hradmin-employee-20260927.sql`、`hradmin-employee-workbench-20260928.sql`，再执行 `hradmin-recruitment-20260928.sql`。已运行过前两份脚本的环境只运行尚未执行的脚本。脚本创建权限点，不自动向角色或租户套餐授权。先在测试数据库验证迁移和完整流程，再部署生产。

首批需要按职责分别授权招聘查询/办理、人员档案、薪酬读写、入职事项以及系统用户管理。`hradmin:employee:query` 当前可读本租户全员，未实现部门级数据范围，不应授予普通主管。
