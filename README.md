# 创界平台交互原型

七个中心 + 总经理工作台。本地网页演示，不连接聚水潭或真实模型。

本轮更新：2026-09-27 流程规则与一致性修正。最新确认规则、测试范围和生产版边界见 [流程规则与一致性修正](交付给技术/流程规则与一致性修正-2026-09-27.md)。下文包含历次迭代记录；已移除功能以最新说明及当前导航为准。

## 启动

在本目录运行 `npm start`，打开 http://localhost:4173 。需要 Node.js，应用无第三方运行依赖。也可使用 `启动创界平台.command`。

目标和业务记录保存在当前浏览器的 localStorage；目标和部门任务附件保存在 IndexedDB。请使用同一个浏览器、同一个网址测试角色切换和刷新恢复。

## 目标管理：当前流程

1. 老板选择接收负责人（主理人还要选择所属店铺），填写目标、为什么要做、要的结果、方案提交期限和目标完成期限。没有资源需求或下属任务表单。
2. 负责人填写验收标准，添加任意数量的里程碑事项，每项填写开始和结束日期；填写交付承诺并勾选确认。支持保存草稿、添加/删除里程碑、规则生成的 AI 建议。
3. 提交老板审核。老板可填写原因驳回；审核通过后立即进入执行阶段。
4. 负责人逐项提交里程碑成果，支持真实文件上传、工作成果内容和 HTTP(S) 链接。每项至少有一份成果才可完成。文件单个上限 10 MB，每次合计上限 30 MB。
5. 全部里程碑完成才可提交老板统一验收。进度按有成果且已完成的里程碑数量计算。
6. 老板验收通过后，目标完成并归档知识库；不通过须填写意见并选择需要整改的里程碑。原成果保留，选中事项恢复待整改；补齐成果后重新申请验收。
7. 验收驳回后，如需调整方案，可重新编辑并提交老板审核，审批前不能继续交付。改动事项或时间的里程碑重新计算完成状态。

目标下不自动派发下属任务。中心负责人在独立的“任务下发”栏目安排员工工作。

### 可测试入口

- 老板首页“下达目标”、重点目标详情、目标列表标题和操作按钮。
- 目标列表计数卡、状态筛选、搜索和清空。
- 负责人草稿、里程碑增删、承诺提交；老板方案审核与驳回。
- 文件上传和下载、成果链接、更新成果、重新调整和历史交付。
- 全部完成后的验收申请、老板驳回与最终完成。
- 方案版本、知识记录关联跳转、目标 JSON 导出、返回列表。
- 工作台切换、待办与审批、首页进度、AI 目标状态查询。
- 同源多标签同步；另一个标签更新时，未提交表单不自动覆盖，提交前检测版本冲突。

### 旧演示数据兼容

首次升级时，将旧原始数据保存到 `chuangjie-platform-demo-v1-before-goals-v2`。旧目标完整副本保存在每条目标的 `legacyGoal`，原过程记录继续保留。

旧目标没有结构化里程碑成果，因此统一进入“待制定方案”，不将旧百分比或旧完成标记直接作为新流程的交付证据。旧主理人目标如果缺少店铺归属，补入其已有的归银堂旗舰店。新下达目标必须明确归属。

## 工作台专属导航

- 总经理：概览、目标管理、AI Agent。
- 主理人：概览、目标管理、任务下发、商品库存、选品、平台服务、AI 助手。
- 供应链：概览、目标管理、任务下发、整理供应商图片库、发现潜力品、商品定价限价、组织清仓、商品生命周期、产品开发。
- 创业者发展：目标管理、任务下发、平台服务受理、人事行政管理、创业者管理。项目全流程管理已移除；跨部门审批从公共待办处理。
- 财务：概览、目标管理、任务下发、对账与资金、风控与盘点、税务与薪酬、经营分析。
- AI 科技：目标管理、任务下发、开发需求。
- 仓储：目标管理、任务下发、盘点任务。
- 视觉：目标、任务下发、拍摄、视频、接收的任务。拍摄与视频暂共用款式基础视觉工单。

公共待办、知识库、平台设置和 AI 入口独立分组。切换工作台后进入该中心首个功能页。

## 其他业务体验

- 主理人选品采购 → 供应链审核 → 财务审核资金 → 供应链采购执行 → 仓储入库 → 自动生成视觉工单。
- 主理人平台服务申请 → 发展中心受理分配 → 承接中心确认范围 → 补充资料 → 交付 → 主理人验收。
- 财务下发盘点 → 仓储接收 → 员工盘点、逐编码差异说明 → 财务复核。
- 中心负责人明确任务、执行人、交付要求、验收标准、起止日期和优先级 → 指定员工确认接收 → 更新进度与阻碍 → 提交成果 → 负责人验收或驳回 → 员工补交 → 验收完成归档。

## 知识库与模型

目标操作会更新知识库过程记录；最终完成后生成交付归档，支持从知识记录返回原目标、查看和下载附件。手工知识可按权限检索。模型对话使用规则演示，目标查询读取当前目标数据，未部署本地模型、未连接真实向量检索。

未来接入流程：服务端身份认证 → 权限过滤 → 文档检索或业务查询 → 本地模型 → 来源引用与审计。浏览器演示角色不是正式的安全边界。

## 范围与限制

- 演示时钟固定为 2026-09-24 10:00 中国时间，日期型截止按当日 23:59:59 解释。操作审计记录使用真实浏览器时间。
- 目标期限到期变黄、满三个自然日变红；批准延期保留灯色，已红灯不恢复；拒绝延期变红。延期不会自动改变里程碑已批准的时间安排。
- 剩余时间 5% 提醒、每周派单和上级推送当前仅展示规则，未实现后台调度。
- 目标和部门任务附件已实现浏览器本地存储与下载；其他工单暂只记录成果说明或文件路径。尚未接入公司文件服务器。JSON 导出含附件元数据，不包含附件二进制内容。
- 税务薪酬、人事行政、清仓等部分外围业务仍为范围预览；定价限价按要求保留待补充入口。
- 金额和经营趋势为模拟数据，未对接交易明细；七个中心各提供两位演示员工，可在顶栏切换；未实现真实登录账号。
- 存储损坏时不覆盖原数据；目标保存失败时不推进流程。

## 全局悬浮 AI

- 右下角固定 AI 图标，任何页面及业务详情弹窗均可打开；原侧栏 AI 入口也打开同一个浮动面板。
- 面板独立于页面渲染；发送问题不会刷新或丢失业务表单输入。收起、切换栏目后保留对话与未发送内容。
- 不同中心、负责人/员工、不同员工使用分开的会话；会话保存在本次页面内存中，刷新网页后不保留对话。
- 可读取当前已打开且有权访问的任务或目标，并给出来源跳转。页面中的未提交表单不会自动发给 AI；打开来源前会检查未保存表单。
- Esc 先收起 AI，再次 Esc 才关闭业务弹窗。支持窄屏布局。
- 当前仍为本地规则演示，没有部署或调用真实模型。

## 部门任务管理

- 负责人仅能向本中心演示员工派单。主理人可为其店铺员工派单，并指定所属店铺。
- 下发字段：任务名称、说明、交付要求、验收标准、执行人、优先级、开始/截止日期；可选关联当前中心目标。
- 待接收阶段可附原因修改要求或重新指派执行人。员工须先接收，才能更新进度或交付。其他员工看不到该任务及对应任务知识记录。
- 员工进度最高 99%，只有负责人验收通过后才为 100%。交付必须提供文件、成果内容或有效链接至少一项。
- 驳回必须有原因；原成果和历史版本保留，再交付后重新申请验收。
- 员工可以申请延期，须由负责人批准；批准保留已有灯色，拒绝则变红灯。存在未处理延期申请时需先审批，再结束任务。
- 与目标的关联仅用于溯源，部门任务完成不会修改目标的里程碑或状态。
- 操作、阻碍反馈、延期审批、交付和验收记录同步到当前任务、双方待办与知识库。
- 旧通用任务自动保留副本并回到待接收，默认路由给原中心第一位演示员工；负责人可先补齐验收标准并调整执行人。原始备份位于 `chuangjie-platform-demo-v1-before-tasks-v2`，每条旧任务包含 `legacyTask`。

## 总经理概览：经营与管理两个视角

总经理导航已由“经营概览”改为“概览”。其他中心本轮保持原有页面。

### 经营视角

- 内置 8 个示例店铺的每日账本，覆盖 2026-01-01 至 2026-09-24。店铺名称、人员、费率、交易金额均为演示，不是实际公司报表。
- 支持全部店铺 / 单店、自定义日期、本月、上月、近 7 天筛选。
- 六个固定字段：销售净额、销售净成本、品牌管理费率、预估平台费率、预估利润额、预估利润率。
- 按用户确认的演示口径：利润 = 净销售 − 净成本 − 净销售对应品牌管理费 − 净销售对应平台费；未纳入其他费用。
- 费用每日以分计算后汇总；公司费率按销售额加权，利润率采用总利润 / 总净销售，不平均店铺利润率。
- 支持上月同期或前一等长周期比较。页面标出具体比较日期；天数不同或对比期越过数据范围时，不计算升降比例。前期为 0 时比例显示不可比较；负利润使用前期绝对值为基数。
- 经营图表、报表、趋势提醒、公司销售占比和利润排名使用同一账本。单店筛选后销售占比分母仍为全公司同期销售。利润排名始终为公司同期全部店铺排名。
- 点击店铺查看六项指标、费用拆解与逐日明细；点击走势图数据点查看当天明细。支持排序、经营汇总 CSV 和店铺日报 CSV 导出。
- 悬浮 AI 在总经理概览回答当前经营 / 店铺 / 利润问题时，读取当前筛选结果。

### 管理视角

- 直接读取现有目标、部门任务和流程记录，不生成虚假的完成率。
- 独立选择计划月份、部门和事项类型。按截止月份归属，保留此前月份未完成事项，避免遗漏跨月积压；不与经营查询日期绑定。
- 七个中心卡片显示目标、员工任务、公司流程分别完成多少，并给出事项完成率。无事项显示“—”，不显示 100%。
- 延期明细可定位目标方案期限、未交付里程碑、任务整体期限、员工反馈阻碍、验收驳回、待审批延期，以及配置了期限的当前流程步骤。
- 目标/任务按责任中心统计；流转中公司流程按当前处理中心统计。例如供应链审核通过后，采购进入财务中心当前队列。
- 流程整体逾期不等于当前步骤逾期。未配置步骤期限时明确标注未知；“步骤与期限”可设置当前及后续步骤日期，要求日期有序且不超过整体期限，并保留理由和过程记录。
- 事项卡片和异常明细可进入原目标、任务、流程查看或处理；数据更新后概览重算。

验证脚本：`node tests/ceo.cjs`，覆盖金额勾稽、加权费率、占比分母、负利润、排名、对比边界、筛选和导出、流程节点期限、跨月事项、里程碑延期、员工阻碍与手机布局。

## 项目运营中心概览

- 事业主理人的导航和页面统一命名为“概览”，采用与总经理相同的经营账本、日期查询及利润口径。
- 当前演示主理人林悦负责归银堂旗舰店、银器生活店。经营查询、分析提醒、趋势、店铺日报、销售占比、利润排名和 CSV 导出均只取这两家店的数据。
- 主理人的占比分母和利润排名限定在自己负责的全部店铺；选单店后，占比仍以自己全部店铺的同期销售为分母。总经理保持全公司口径。页面和导出均注明范围。
- 总经理和主理人的日期、店铺、排序筛选分别保留，不会把总经理选择的其他店铺带入主理人界面。
- 管理区按“公司下达给我的目标 / 我给员工下发的任务 / 我的跨部门协作”分类，可按月份、自己的店铺、事项类型和状态筛选，并追踪延期、阻碍与当前处理人。
- 员工任务卡可下钻到本人派单给该员工的任务；事项详情使用原目标、任务和协作流程，不复制第二套进度。
- 切换为项目运营中心员工时，仅显示分配给该员工的任务，不展示主理人经营汇总。
- 非总经理身份的“平台设置”改为“个人设置”，不提供全局审计日志或批量平台数据导出。相关操作记录保留在其有权访问的任务和流程详情中。
- 这些是原型的数据范围过滤，真实服务端身份认证、行级权限与审计授权仍需后续实施，不能将前端过滤当作生产安全边界。

### 供应链中心闭环（2026-09-25）
- 概览的四项指标读取业务记录，支持月份和来源明细：已发布到运营的新增商品主图数（一个商品一张主图）；运营本月填写的各清仓单最新预估金额（累计快照不重复累加）；本月完结的开发单；本月主管通过的潜力品。
- 图片整理：周期任务 → 员工文件夹导入 → 自动按“供应商/分类/商品/图片”归组 → 编辑名称、克重、工费等 → 覆盖情况确认 → 负责人审核发布 → 运营同步。支持真实本地图片，IndexedDB存储；同路径同内容去重，未发布商品不进入运营选品。已发布资料可更新而不重复计新增数。
- 清仓：每月两次周期任务 → 多SKU模拟查询、原价/清仓价/优惠和目标金额 → 指定项目及评价人 → 主理人接收、累计销售数据和复盘 → 指定负责人评论、1–5星评分 → 完成。可退回补充；目标销售额和运营预估金额分开记录。
- 潜力品：快速记录图片/想法 → 分次保存五维评分、说明、链接及附件 → 主管评审或退回 → 通过纳入概览。持续跟踪可随时追加，不丢失同时填写的评分草稿。

### 每月潜力品任务与供应链产品开发
- 潜力品每月两次周期任务，默认1日、16日，周期规则中可调整日期、期限及负责人。每期关联独立潜力商品研究记录，主管退回则继续研究，关联商品全部通过后自动完成；至少有一款关联商品才可完成，单纯生成周期任务不计入潜力品成果数量。
- 产品开发必填：开发理由、预计零售价、受众群体、产品定位、竞争优势、可能问题。申请缺项不能提交。
- 开发流程：负责人立项审核并分配供应链产品设计师 → 指定设计师上传真实效果图 → 供应链负责人审核并指定跟样人 → 谈价、打样、跟踪到货 → 负责人品质验收 → 完成。跟样人支持负责人本人；样品不合格退回跟进，禁止提前完成；不再流转到视觉美工或采购阶段。
- 本中心新增演示员工“小唐 · 产品设计师”（emp-2-3）。效果图上传验证真实可解码图片，支持下载、放大查看和历史版本；纯文字、没有图片或非图片附件不能进入效果图审核。
- 旧未完开发单保留legacyDevelopment和localStorage备份，回到“开发依据退回补充”；历史完成单保留完成状态，不伪造补齐资料或日期。
- `node tests/development.cjs` 覆盖缺项校验、图片与岗位限制、效果图退回、样品不合格退回、负责人本人跟进、迁移、完成指标、潜力品周期生成/去重/补生成及评审联动。

### 商品生命周期（商品档案与销售任务）
- 产品供应链中心 → 商品生命周期：添加或批量查询商品编码、查看图片与基础资料、按店铺和日期查询销售金额/数量及退款金额/数量，保存维护记录。

### 仓储盘点：季度大盘与月度抽盘
- 仓储履约中心 → 盘点任务：按类型、状态、周期/名称/编号查询；显示盘点进度、盘亏/盘盈数量、逐款追因进度、当前处理人与期限。
- 季度大盘固定包含全部600款演示商品（含零库存款）；月度随机抽取50–150个不重复编码。清单、库位、账面数量和参考成本在创建时保存快照，刷新和重复检查均不重新抽码。
- 默认每月1日生成月度任务，每季首月1日生成季度任务，演示期限分别7/14个自然日。仓库负责人可修改后续任务的接收仓管员与期限，通过“周期规则与演示日期”推进日期演示自动触发。浏览器打开或推进演示日期时检查周期，没有后台常驻调度服务。
- 初始化提供本季大盘、本月抽盘；旧未结案事项保留原资料并重新逐码盘点；旧已结案事项保留结案状态，不伪造历史实盘数字。
- 指定仓管员（默认小王）接收 → 全部编码填写实盘数量 → 对每款差异主动标记盘亏/盘盈并记录原因及问题点 → 仓库负责人逐款填写盘亏损失金额/盘盈可能原因，以及下次优化方向 → 财务负责人或小赵会计记录处理结果并结案。
- 未盘点为空，实盘0明确代表无库存。查找和翻页保存当前页，跨页提交校验整份清单；差异标记必须与数量差异一致。支持盘点修正、仓库退回追因、财务退回复核、CSV导出、结案知识归档。全部库存正常仍需负责人记录优化方向并经财务结案。
- ERP、库存与账务均为演示，不实际调整聚水潭库存或生成会计凭证。测试：node tests/stock.cjs。

### 视觉中心：图片、视频与其他部门任务
- 图片任务、视频任务独立显示，主管审核时选择一般/重要/紧急、具体执行人、期限和交付要求。图片默认小许设计师，视频默认小周摄影师；员工仅查看本人已分配任务，列表优先显示紧急、重要事项。
- 主管审核分配 → 员工接收 → 上传真实工作成果 → 主管验收 → 完成。没有文件不能提交或验收；主管退回后重新上传，历次文件和审核意见保留。
- 文件自动命名为商品编码-图片.扩展名或商品编码-视频.扩展名，多文件添加-02、-03等序号。归档规划按固定盘/商品编码/任务编号/v版本分目录，避免同名覆盖。主管可调整固定盘路径，已有版本保持原路径记录。
- 当前附件实际保存在浏览器 IndexedDB，支持图片/视频预览和原内容下载；固定盘路径是可配置的归档规划，尚未连接公司文件服务器，不会声称已经写入固定盘。单文件200MB、每次总计500MB/30个文件以内，存储失败不推进任务。
- 首次入库演示为同款生成图片、视频两张工单，重复触发不重复创建。旧综合工单保留历史后拆分；未完成任务重新由主管审核分配。
- 其他部门平台服务关联视觉子任务：视觉主管先审核分配，完成后审核本中心交付，再进入原平台服务的主理人验收。主理人退回会同步重开视觉制作；原服务只有主理人确认后才完成。
- 验证：node tests/visual.cjs，覆盖真实图片/视频上传、预览、下载、自动命名、版本保留、权限、优先级、主管验收、平台服务退回重交和刷新持久化。

### 平台服务分流：视觉服务直接排期
- 项目运营中心平台服务入口分为视觉服务、其他服务。原有未分类记录继续按其他服务处理，不自动改变历史流程。
- 新视觉服务由主理人填写要求说明、一般/紧急/重要及期望完成日期，直接生成视觉中心“其他部门任务”中的关联工单，不经过发展中心。
- 视觉负责人保留主理人优先级，填写实际开始/结束排期并分配设计师或摄影师；实际完成日期晚于期望时必须说明原因。申请中保留期望日期并同步展示实际排期。
- 员工接收并上传成果后，由视觉负责人审核；通过时关联工单和视觉服务同时完成，主理人查看、下载成果，无需再次验收。主管退回仍由原执行人修改。
