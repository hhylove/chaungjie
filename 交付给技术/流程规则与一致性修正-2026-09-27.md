# 创界平台：流程规则与一致性修正

日期：2026-09-27。此文件补充生产系统规划书，记录本轮确认的规则、原型实现与验证边界。原型仍为本地演示，不是生产办公系统。

## 一、已确认的规则

| 事项 | 统一口径 |
| --- | --- |
| 延期 | 使用北京时间、自然日；日期截止至当日结束。批准延期最低黄灯，已有红灯不降级；拒绝延期沿用原期限。当前实现按超过截止时刻满 72 小时进入红灯。 |
| 驳回 | 原因和整改提交期限必填；整改不能隐式修改总期限。超过总期限时先审批延期。 |
| 管理层 | 总经理、创业者发展中心总监。新制度、新模板及关键内容变更由总经理审核；已有文件的一般维护、签署协议归档由发展总监审核。创业者最终立项仍由总经理审批。 |
| 撤回与终止 | 未接收、未审批的申请可由发起人撤回；启动后申请终止，由原任务下发人或流程负责人确认。总经理目标由总经理终止。历史记录保留，终止不算完成。 |
| 期限 | 普通审批默认 2 个自然日；执行按任务、排期或负责人确认的期限。节点期限不能超过总期限。刷新页面不能自动延长截止时间。 |
| 知识 | 过程与成果保留原访问范围。部门经验经负责人审核后生成独立公司共享摘要，不直接开放原任务与全部附件。制度、模板只检索最新生效版本；个人档案、薪酬、个人签署合同不进入全员知识库。 |

## 二、本轮原型修改

- 公共待办与原业务表单复用相同命令，避免“公共审批已通过，但档案、版本或库存没有改变”。调薪结案更新员工档案；文件审批保留版本冲突校验并生成签收；创业者物资批准时预留行政库存；销售审批保留是否入账选项，需入账的结案要求凭证号。
- 公共待办按真实当前节点分派，同阶段可并行的必要事项分别展示。“员工本人”通过人员账号 ID 分派，不再随意归给中心负责人。人事经办与负责人审批分开。
- 统一展示全部、待我处理、我已处理、临近到期、黄灯、红灯、已完成和撤回/终止条数。“我已处理”与“整条流程已完成”采用不同口径。
- 审批详情展示申请正文、本次原附件、上一生效版本原附件、流程步骤和办理记录；原文件保存在该浏览器的 IndexedDB，缺失时明确提示，不以附件名称代替文件。
- 新增撤回、恢复、终止申请及审批入口。终止后的完整流程显示停止位置和未执行步骤，保留审计记录。
- 制度、采购、销售被驳回后进入人事整改待办；涉及专门字段或凭证时进入对应业务表单补齐，不用一个“通过”按钮代替实际办理。销售重提会重新核对并锁定库存。
- 新操作记录具体人员身份、时间、动作及阶段。节点贡献统计仅采用有实际身份的操作记录；没有真实经办证据的旧流程不按阶段猜测员工贡献。历史演示节点仍单独标注，系统生成任务不计入。
- 人事与创业者模块继续独立存储业务资料，共用平台人员身份。普通创业者服务员工不因进入发展中心就自动获得人事管理权限。
- 知识查询与演示 AI 采用同一可见范围；共享摘要须经本中心负责人审核。签署合同保留在协议合同业务中。

## 三、代码入口

| 文件 | 用途 |
| --- | --- |
| `hr/workflow-policy.js` | 自然日期限、文件审批角色、整改、撤回终止的公共规则 |
| `hr/operations.js`、`hr/onboarding.js`、`hr/engine.js` | 文件、物资、创业者手续及人员流程的业务命令与副作用 |
| `cross-approvals.js` | 将不同模块当前节点映射为公共待办，调用业务命令，读取原附件 |
| `ui-enhancements.js` | 待办计数、本人已办、流程详情、附件与期限操作 |
| `workflow-governance.js` | 主平台撤回终止、操作证据、知识共享及权限范围演示 |
| `workspace-experience.js` | 完整流程、当前节点、停止位置等统一展示 |

生产版应将这些规则迁到服务器上的统一工作流/业务服务，前端只提交命令，禁止在不同页面分别实现审批逻辑。

## 四、验证记录

执行 `npm run check`，以及：

```sh
node --test tests/workspace-design.cjs tests/workflow-integration.test.mjs tests/governance.test.mjs hr/*.test.js
```

本轮共 46 项逻辑回归用例。覆盖日期边界、延期灯色、整改期限、节点期限持久化、调薪结案、并行节点、本人确认权限、文件版本冲突及签收、库存预留、销售入账、销售整改重提、审批角色、撤回终止、知识范围和节点统计。

浏览器实际验证：

1. `CJ-119 / 规则验证 · 撤回与终止测试`：撤回 → 恢复 → 员工接收 → 发起人申请终止 → 负责人批准；已终止记录单独保留，未计入完成。
2. `演示验证 · 知识共享审批`：员工录入内部资料 → 提交独立共享摘要 → 中心负责人批准 → 切换供应链中心，仅可见公司共享版，未见原部门正文。
3. 页面加载和上述交互无新增 JavaScript 错误。

验证不是所有历史页面、所有状态排列的穷举验收。旧的浏览器测试含已废弃导航文案断言，不能作为本轮新版 UI 的全量验收依据。测试中保留的旧引擎兼容用例不代表恢复了已移除的“测试/正式”页面或“项目全流程管理”入口。

## 五、技术落地边界

- **身份和权限**：顶部切换器仍是演示角色，不能视为安全隔离。生产版须使用登录身份及服务端 RBAC + 数据范围校验，文件下载、导出、检索、审批 API 全部重新鉴权。
- **持久化和事务**：演示数据保存在 localStorage，原文件保存在 IndexedDB。跨模块保存有并发检查和失败回滚尝试，但浏览器多存储写入不等同数据库事务；生产版必须使用数据库事务、唯一约束、幂等键和可恢复的事件投递。
- **日期**：新流程使用当前自然日。供应链和盘点已有可调演示日期，经营报表仍为固定期间的样例数据。历史流程缺少原期限时会显示待核定的默认期限，不能当成真实历史日期迁移。
- **撤回终止**：已发生库存出入库、资产领取或已发布有效文件不得直接抹除，需要相应归还、冲销、废止或变更业务；生产版逐类配置补偿动作。已停用流程和业务模块的历史数据应只读保留。
- **文件与知识**：没有接入公司固定盘、文件内容解析、向量索引或 4090 上的本地模型。未来建立不可变文件 ID、版本、归属流程、密级、校验值、权限索引；知识授权变更后同步撤销索引和缓存。共享不能依赖文件路径或文件名鉴权。
- **其他集成**：本轮未接入真实聚水潭、企业微信、账号开通、外网部署、自动定时任务和真实财务。业务原型已展示的步骤不等同这些集成已完成。
- **上线验收**：技术需补齐服务端权限矩阵、账号离职交接、附件备份恢复、每类流程的驳回重提/撤回终止/并发审批测试，再迁移员工资料。不得直接迁移虚构演示人员和历史演示节点。
