# 创业者发展中心整合版

## 2026-09-26 创业者模块独立修正

创业者管理现使用独立页面 founders.html 和独立业务存储 chuangjie-founders-v1。仅有“创业者人员、招募、协议与合同”三个页签。人员列表显示名称、职务、项目、测试/正式状态；招募立项后默认测试。设置测试目标、期限和资金后，按期达标上传证据，须总经理审批才转正式。办公资产在创业者档案中由人事申请、总监审核、人事派发并上传领取凭证，可办理归还。

首次进入会从旧混合版复制已有创业者、招募、协议、项目及领用记录，保留原始记录备查，之后独立保存，互不写入人事员工、招聘或制度列表。人事行政仅保留人员、招聘、流程、制度与档案、行政物资仓库。项目管理仍由平台单独入口进入，与创业者档案关联。

新增验证：`node --test hr/founders.test.js`，覆盖立项不新增员工、资产审核门禁、按期达标与正式审批。浏览器验证了三个专属页签、历史协议保留、资产申请到审核派发，以及人事行政菜单不混入创业者功能。

入口：http://localhost:4173 → 创业者发展中心。

人事行政管理中保留人员、招聘、流程、制度与档案，并增加行政物资仓库。平台侧创业者管理和项目全流程管理分别打开同一套数据的对应页面。原有平台服务受理保留在项目全流程管理页面下方。所有代码随平台本地运行，不依赖原 5176 服务。

## 测试身份

模块内部的“模拟处理角色”用于演示人事专员、创业发展总监、管理层、财务负责人、总经理等岗位操作。它不是正式登录授权；新流程暂在本模块办理，不汇入平台公共待办或总经理节点统计。平台原有任务和业务数据保留。

## 测试路线

1. 招聘：候选人 → 面试 → 评价 → 总监录用审批 → 人事转员工。已取消 Offer 签收；历史停在 Offer 的记录自动转待入职，旧审批记录保留。
2. 制度与档案：人事新增或更新，支持多文件上传、正文、变更理由、签收员工；管理层批准才形成有效版本与签收任务。驳回后修改重提，旧版可下载。
3. 行政物资：人事采购申请 → 财务负责人审核 → 人事上传到货凭证 → 发展总监确认入库。有价资产逐件编码，记录价值、折价年限、领用人；易耗品按数量扣库存。支持派发、归还、换发、损坏标记。员工离职资产核验会检查仓库未归还资产。
4. 物资销售：人事申请原因及剩余价值 → 财务审核并决定入账要求 → 人事登记实际售价及凭证 → 财务入账或说明无需入账后结案、扣库存。审批期间物资锁定，避免重复派发或销售。
5. 创业者：总监提需求 → 人事记录渠道和候选人 → 面谈 → 人员评估 → 人事代上传项目计划书 → 项目评估 → 立项。立项后自动建主理人档案；全职员工可直接登记为雇佣主理人。一个主理人可建立多个项目。
6. 筹备：人事上传经营合作协议、创界平台服务协议，管理层审批归档；人事提交手续及物资核验凭证，发展总监审核。协议版本可持续更新，原版本保留。
7. 项目：发展总监填写负责人、店铺及营业执照、三阶段目标/预算/截止日期 → 总经理审核。通过后批准第一阶段预算，发展总监每月记录预算使用、目标达成率、评估和文件证据。按期100%达标后才可申请下一阶段预算，并须总经理审批。月评修改保留历史。

## 数据与验证

- 本机 localStorage 保存业务记录，IndexedDB 保存真实附件（每个文件最多10MB）。导出 JSON 仅包含附件元数据，不含文件内容；下载文件需在原上传浏览器及同一网址使用。
- 整合版未迁移原5176端口的浏览器测试记录。不要清除浏览器数据。演示角色、文件和账务记录不等同正式权限、合同签署、ERP或财务系统操作。
- 折价估算使用直线法、零残值；仅用于原型展示。
- `npm run check`：主平台与新增模块语法检查。
- `node --test hr/engine.test.js hr/operations.test.js`：招聘、档案审批、采购、资产、销售、创业者与项目规则测试。
- 浏览器实际测试：文件上传/审批/下载（下载内容与原文件一致），采购入库独立资产编码；创业候选人到立项、两份协议审批、人事手续、项目审批、月评及第二阶段预算审批。

## 创业者立项后手续（2026-09-26 更新）

最终立项节点由总经理审批。通过后自动进入创业者人员并出现四项待办：

1. 人事申请 OA 账号、必要权限和数据范围 → 发展总监审核 → 人事确认开通。仅演示办理，不实际开通外部 OA、不保存密码。
2. 人事维护职务、项目、联系方式、合作日期、履历及附件 → 总监核验。修订保留旧档案。
3. 从人员档案选择两份协议，上传双方签署文件 → 管理层审核 → 自动归档至协议与合同。合同区顶部上传仅为公司模板，模板新增和更新也经管理层审批；保留版本与附件。
4. 人事从行政仓库选择在库物资 → 总监审核并预留 → 人事上传领取凭证 → 同步出库和领用记录。易耗品扣数量，有价资产保留创业者领用人并支持归还。

四项完成后创业者人员页对应待办自动消除。人员和招聘数据仍分属独立模块，物资操作关联同一行政库存。旧手工资产记录保留但不冒充已出库记录。行政仓库中创业者领用资产须回到创业者人员档案归还，防止两侧记录不一致。

验证：26 项纯逻辑测试通过；浏览器验证账号审批开通、档案审核、物资预留领取、行政库存领用人同步、模板审批生效，以及人员手续 4/4、待办 0 的显示。所有数据仅为当前浏览器本地原型数据。

## 两个板块统一界面优化

- 人事行政：人员总览及档案、招聘、流程、制度文件、库存、采购、派发归还和销售统一卡片、表格、表单与抽屉样式。
- 招聘与创业招募：候选人跟进/用人需求分页，姓名与岗位搜索、阶段筛选，详情显示步骤、当前责任人、跟进记录。提交办理后返回更新后的流程。
- 行政仓库：库存台账/采购与入库/派发归还分区，按编码、名称、领用人和状态查询；采购表单即时显示总额。采购及销售详情显示完整审批流程。
- 制度档案：有效文件卡片、新增更新审批、签收记录分页，搜索及审批状态数量。创业者人员增加搜索和未完成事项筛选。
- 验证：23项人事业务测试通过；浏览器检查招募、招聘、文件页面和流程详情，实际完成演示纸巾采购10件（总额50元）到入库，验证状态更新与库存同步。浏览器错误日志为空。
